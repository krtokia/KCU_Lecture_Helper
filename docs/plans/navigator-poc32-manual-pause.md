# Navigator POC 3.2: 수동 일시정지 안전성 검증

## 목표

한 차시 POC 실행 중 사용자가 영상 플레이어에서 직접 일시정지한 경우 Navigator가
영상을 재생시키거나 다음 차시를 선택하지 않는지 확인한다. 사용자가 직접 재생을
재개한 뒤에도 같은 차시의 실제 종료와 출석 재조회가 정상 동작하는지를 기록한다.

## 현재 상태 확인

- 로컬 연결된 Navigator POC 3.1(0.3.2)은 두 번의 실제 단일 차시 실행에서
  `PASS_NATIVE_END`와 새 목록 응답의 출석 `Y`를 확인했다.
- 두 실행 모두 이미 출석 `Y`인 차시는 건너뛰고 한 차시만 선택한 뒤 `FINISHED`로
  끝났다. 다음 차시 자동 선택·재생은 관찰되지 않았다.
- 현재 3.1은 비종료 pause를 기록하지만 이를 수동 일시정지 검증 결과로 분리하지
  않고 계속 관찰한다.

## 범위와 비목표

### 범위

- POC 이름/버전을 3.2/0.3.3으로 올리고 수동 일시정지 대기·수동 재개 확인 상태를
  추가한다.
- 수동 pause 후 자동 재생을 하지 않았음을 리포트 이벤트와 결과에 남긴다.
- 재개 뒤 기존의 단일 차시 종료·출석 재조회 절차를 그대로 수행한다.

### 비목표

- 다음 차시 또는 다음 과목으로 자동 진행
- 사용자의 pause를 자동 해제하거나 `video.play()`를 호출하는 기능
- 출석·재생 시간·진도 값 조작
- Windows/ntfy 알림 구현(후속 별도 변경)

## 제약과 설계

- 수동 여부를 iframe DOM으로 추측하지 않는다. 끝부분이 아닌 실제 `pause`를
  `NON_END_PAUSE_OBSERVED`로 관찰하고, 사용자가 명시적 재개 이벤트를 만들 때까지
  기다린다.
- pause 뒤에는 POC가 재생 버튼을 누르지 않는다. 지정된 시간 안에 실제 `playing`
  이벤트가 오지 않으면 실패로 끝내며 다음 차시를 선택하지 않는다.
- 기존의 종료 후보, 10초 유예, 새 주차 AJAX 응답 출석 확인은 변경하지 않는다.
- Helper의 배속·알림 코드는 건드리지 않는다.

## 영향 컴포넌트

- `src/kcu-auto-navigator.user.js`
- `docs/TEST_CHECKLIST.md`
- `docs/HANDOFF.md`
- 이 계획 문서

## 수용 기준

- 3.2 메뉴로 시작한 POC는 미수강 영상 한 차시만 선택한다.
- 실제 재생 뒤 끝부분이 아닌 pause를 받으면 `WAIT_MANUAL_RESUME` 상태와 pause
  이벤트를 리포트에 남긴다.
- 대기 중 코드가 영상 재생·차시 선택을 수행하지 않는다.
- 사용자의 실제 재개 후 `MANUAL_RESUME_CONFIRMED`를 남기고 같은 차시만 관찰한다.
- 종료 뒤 새 목록 응답에서 대상 출석 `Y`를 확인하면 `PASS_NATIVE_END`로 끝난다.
- 재개가 없으면 명확한 실패 결과로 끝나며 다음 차시를 실행하지 않는다.

## 검증 계획

1. Node 문법 검사와 정적 검사로 3.1 메뉴·범위가 남지 않았는지 확인한다.
2. 로그인된 강의실에서 한 탭만 열고 POC 3.2를 시작한다.
3. 실제 재생을 확인한 뒤 끝부분이 아닌 시점에 사용자가 플레이어 UI로 pause한다.
4. 최소 15초 동안 자동 재생·다음 차시 선택이 없는지 확인한 뒤 사용자가 직접 재생을
   재개한다.
5. 완료 리포트에서 pause, 수동 재개, 실제 ended, 출석 재조회, 단일 차시 범위를
   확인한다.

## 구현 결과

- Navigator만 `0.3.3` / POC 3.2로 변경했다. Helper와 배포 URL은 변경하지 않았다.
- `pause`는 이미 실제 재생을 확인했고, 같은 대상·플레이어에서, 끝부분/ended/
  seeking/loop가 아닌 명시적 `pause`일 때만 검증 대상으로 삼는다.
- `WAIT_MANUAL_RESUME`은 5분 한도이며, 같은 플레이어의 명시적 `playing`만
  `MANUAL_RESUME_CONFIRMED`로 기록한다. POC가 `play()`를 호출하지 않으므로 이는
  실제 재개 관찰값이지 자동 재개가 아니다.
- POC 목적상 pause·resume 증거가 없는 종료 후보는 성공으로 처리하지 않는다.
  실제 KCU/Tampermonkey 실행은 사용자 리포트 대기 상태다.

## 3.2.1 초기 pause 보정

첫 POC 3.2 실제 실행에서 사이트가 `playing` 직후 약 0.8초 지점에 자체 `pause`를
발생시켰다. 사용자의 조작이 아닌데 기존 조건이 이를 `NON_END_PAUSE_OBSERVED`로
분류해 곧바로 `WAIT_MANUAL_RESUME`으로 진입했다.

수정은 POC 버전을 `0.3.4`로 올리고, 같은 실제 영상의 `currentTime`이 최소 10초에
도달하기 전의 non-end pause를 `STARTUP_PAUSE_IGNORED`로 기록한 뒤 관찰을 계속하는
것이다. 10초 이후에만 기존의 수동 pause 검사로 진입한다. 종료 판정·재개 대기·한
차시 범위·영상/진도/출석 조작 금지에는 변경이 없다.

검증은 3강을 새로 시작해 초기 사이트 pause가 무시되고 실제 재생이 10초를 넘는지,
그 뒤 사용자가 플레이어 UI로 pause했을 때에만 `WAIT_MANUAL_RESUME`으로 들어가는지
확인한다.

## 3.3 전체 진단 타임라인

### 목적

중간 pause가 특정 재생 위치의 플레이어 동작인지, 플레이어 포커스/사용자 입력과
인접한 동작인지 구분할 수 있도록 한 실행의 시작부터 종료까지 진단 타임라인을
남긴다. 2026-09-10 완주 리포트에서는 `45.232초` pause 직전 90ms에 상위 창 blur와
iframe focus가 있었지만, 현재 15초 간격 샘플만으로 원인을 단정할 수 없었다.

### 설계

- POC를 `0.3.5` / 3.3으로 올리고, iframe probe가 각 video의 미디어 이벤트
  (`play`, `playing`, `pause`, `waiting`, `stalled`, `seeking`, `seeked`,
  `ratechange`, `timeupdate`, `ended`, 오류)을 작은 진단 레코드로 전달한다.
- iframe/top-level focus·blur·visibility와 사용자 입력은 이벤트 종류, trusted 여부,
  대상 유형, 좌표 유무만 기록한다. 키 입력 문자, URL, RPC 원문, 세션 값은 기록하지
  않는다.
- 타임라인은 최대 5,000건의 순환 버퍼로 보관한다. 짧은 강의의 전 구간을 목표로
  하되, 장시간 강의에서 무한한 메모리·리포트 크기 증가는 막는다.
- 타임라인 수집은 관찰 전용이다. `play()`, `pause()`, currentTime/진도/출석 조작,
  다음 차시 선택을 추가하지 않는다.

### 수용 및 검증 기준

- 리포트에 타임라인과 누락 건수가 분리되어 나타난다.
- 중간 pause 전후에 해당 video 위치, 미디어 이벤트, focus/visibility, trusted 입력
  흔적을 시간순으로 비교할 수 있다.
- 기존 POC 3.2.1의 시작 pause 무시·수동 재개·native ended·새 AJAX 출석 확인은
  유지한다.
- POC 3.3은 진단 목적이므로 중간 pause가 발생하지 않은 실행도 native ended와 출석
  확인까지 통과시킨다. pause가 발생하면 기존처럼 재개를 기다려 기록하며, 결과의
  `nonEndPauseObserved`/`manualResumeConfirmed`로 여부를 구분한다.
- Node 문법 검사와 금지 조작 정적 검사를 통과하고, 실제 짧은 강의 한 회 리포트로
  타임라인이 끝까지 수집됐는지 검증한다.

# Navigator POC 3.5: 첫 과목부터 첫 미수강 과목 탐색

## 목표

현재 선택 과목과 무관하게 LNB 첫 과목부터 순서대로 탐색한다. 열린 주차에서 출석 N·영상
Y인 차시가 있는 첫 과목을 찾고, 그 과목의 첫 적격 차시를 사이트 버튼으로 한 번만 시작해
실제 `playing`을 확인한 뒤 종료한다.

## 현재 상태 확인

- POC 3.4는 동일 과목 안에서 다음 차시 한 개의 재생까지 이미 반복 실측했다.
- LNB 과목 링크는 form POST를 통해 전체 페이지를 이동한다. 따라서 JavaScript 메모리는
  다음 과목에서 사라진다.
- 직전 POC 3.5의 현재 재생 차시 인계 설계는 동일 과목 다음 차시를 다시 검증하는 중복
  범위였고, 사용자의 의도와 다르므로 교체한다.
- 첫 실측은 6개 과목을 순서대로 통과해 서비스마케팅 2주 1강을 정확히 찾았으나,
  차시 스냅샷에 의도적으로 제외한 DOM 버튼 참조를 다시 읽으려 해 클릭 직전에 실패했다.
  대상 버튼은 스냅샷이 아닌 현재 `#videoInfoBody` DOM에서 차시 번호·출석·영상 상태를
  다시 대조해 찾아야 한다.

## 범위와 비목표

- LNB DOM 순서상 첫 과목부터 한 번씩만 검사한다.
- 페이지 이동 사이에는 실행 ID, 탐색 인덱스, 현재 과목의 비민감 식별값, 단계만 GM
  저장소로 넘긴다.
- 첫 미수강 과목의 첫 적격 차시에서 실제 playing까지만 확인하고 종료한다.
- 한 영상 종료 뒤 계속 재생, 두 번째 미수강 차시, 두 번째 과목의 영상 재생, 진도/출석
  API·media 시간·배속 직접 조작은 하지 않는다.

## 제약과 설계

- 과목 이동 직전 LNB 링크의 `data-cose-cd`와 현재 과목 ID가 달라야 하며, 탐색 인덱스는
  증가만 한다. 이동 후 URL/메모리가 아닌 새 DOM form·LNB ID로 목적 과목 도착을 확인한다.
- handoff는 10분 안에 다음 페이지에서 소비되지 않으면 만료해 자동 동작하지 않는다.
- 초기 AJAX 및 새 주차 DOM을 검증한 뒤에만 적격 차시 여부를 판정한다.
- 사용자 과목/주차/차시 조작, handoff 불일치, 페이지 이동 시간 초과, 신호 공백은 다른
  과목/차시 대체 없이 중단한다.

## 수용 기준

- 현재 과목이 아닌 LNB 첫 과목부터 순서대로 검사한다.
- 미수강이 없는 과목은 한 번의 실제 LNB 클릭으로 다음 과목으로 넘어가며, 도착 검증 전
  차시 버튼 클릭이 없다.
- 첫 미수강 과목에서만 첫 적격 차시 버튼 클릭과 실제 playing 확인이 한 번 있다.
- 버튼을 못 찾거나 대상의 현재 DOM 상태가 서버 응답과 달라지면 클릭하지 않고 실패한다.
- 모든 과목에 적격 차시가 없으면 `NO_TARGET_ALL_COURSES`로 끝난다.
- 리포트에 과목 탐색 순서·결과·최종 대상·페이지 이동 handoff를 남기되 URL·세션값은 없다.

## 검증 계획

1. 두 UserScript 문법 검사, handoff 데이터의 허용 필드·만료·단조 인덱스 정적 검사,
   `git diff --check`.
2. Node 모의 GM 저장소로 handoff 생성·소비·만료·과목 ID 불일치·모든 과목 완료의
   경계를 검사한다.
3. 실제 KCU에서 첫 과목부터 탐색해 한 번 이상 과목 이동, 첫 미수강 차시의 실제 playing,
   세 번째 차시/두 번째 영상 재생 없음이 리포트에 남는지 확인한다.

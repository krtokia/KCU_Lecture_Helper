# 로컬 Tampermonkey 개발 연결 계획

## 목표

GitHub Raw 배포본과 분리된 개발용 Tampermonkey 설치본이 이 저장소의 로컬
`src/*.user.js`를 읽도록 연결한다. 기존 배포용 설치본은 비활성화하고, Helper와
Navigator는 각각 하나의 개발용 설치본만 활성화한다.

## 현재 상태 확인

- 작업 트리는 변경 사항이 없다.
- 실행 소스는 `src/kcu-lecture-helper.user.js`(1.0.4)와
  `src/kcu-auto-navigator.user.js`(0.3.2)다.
- 두 파일의 GitHub Raw `@updateURL`/`@downloadURL`은 유지되어 있다.
- Navigator POC 3.1은 2026-09-10 한 차시 실행에서 실제 `ended`와 새 목록 응답의
  출석 `Y`를 확인했다. 전체 시청 여부는 검증하지 않았다.
- 이 환경에서 Tampermonkey의 실제 설치본·파일 연결 상태는 아직 확인하지 않았다.

## 범위와 비목표

### 범위

- 기존 POC/배포 설치본을 비활성화하고, 로컬 파일을 따르는 개발용 설치본을 만든다.
- 로컬 저장이 Tampermonkey 편집기와 페이지 새로고침 후 실행 코드에 반영되는지를
  확인한다.
- 실제 연결 결과와 미검증 상태를 HANDOFF 및 체크리스트에 기록한다.

### 비목표

- Helper와 Navigator의 기능 통합·확장·재작성
- 출석, 재생 시간, 진도 값의 조작 또는 전체 시청 여부의 추정
- GitHub push, Raw 배포 경로 변경, Greasy Fork 게시

## 가정 및 제약

- 사용자는 기존 GitHub 연동 설치본 또는 POC 설치본을 직접 비활성화할 수 있다.
- Follow file on disk 기능을 우선 사용한다. 해당 기능 또는 파일 권한이 없으면
  별도 개발용 로더에 로컬 `@require file:///...`를 두는 방식으로 전환한다.
- 로컬 파일의 UserScript 헤더 변경은 로더 메타데이터에 자동 반영되지 않는다.
- 실제 강의실 검증은 로그인된 사용자 세션과 한 개 강의실 탭이 필요하다.

## 제안 설계

1. Tampermonkey 대시보드에서 기존 Navigator POC와 GitHub Raw 배포 설치본을
   비활성화한다. Helper는 필요한 경우 기존 배포본도 비활성화한다.
2. 각 로컬 `.user.js`를 개발용 설치본에 연결한다.
   - 우선: 편집기의 **File → Follow file on disk**로 각각 대응 파일을 선택한다.
   - 대안: 원래 메타데이터를 가진 빈 개발용 로더에 해당 로컬 파일의 `@require`
     한 줄만 둔다.
3. 각 스크립트는 하나만 활성화된 상태를 확인한다.
4. 식별 가능한 무해한 코드 표식으로 로컬 저장 반영을 확인한 뒤 즉시 원복한다.
   이 작업은 기능이나 배포 메타데이터를 바꾸지 않는다.
5. 강의실을 새로고침하여 Helper/Navigator의 시작 로그 또는 메뉴가 한 번만
   나타나는지 확인한다. Navigator의 자동 실행 메뉴는 누르지 않는다.

## 영향 컴포넌트

- Tampermonkey 개발용 설치본과 로컬 파일 연결
- `docs/HANDOFF.md`, `docs/TEST_CHECKLIST.md`
- 필요 시 이 계획 문서

## 수용 기준

- 배포 설치본과 개발 설치본이 동시에 활성화되지 않는다.
- 각 개발 설치본은 해당 로컬 `src/*.user.js` 하나만 참조한다.
- 로컬 파일 저장 후 편집기 본문 반영을 확인한다.
- 페이지 새로고침 후 대상 스크립트가 한 번만 실행되는 것을 확인한다.
- 배포용 URL, 버전, 기능 코드는 변경하지 않는다.
- 실제 브라우저 접근이 불가하면 그 사유와 사용자가 수행할 최소 확인 절차를 남긴다.

## 검증 계획

1. `node --check`로 두 실행 소스의 문법을 확인한다.
2. Tampermonkey 대시보드에서 활성화 개수와 파일 추적 상태를 확인한다.
3. 로컬 파일의 무해한 임시 표식을 저장·확인·원복하여 디스크 추적을 검증한다.
4. Orca 내장 브라우저 또는 연결된 데스크톱 브라우저에서 강의실을 새로고침하고,
   메뉴/로그가 중복되지 않는지 확인한다. 로그인 세션이 없으면 이 항목은 미검증으로
   기록한다.

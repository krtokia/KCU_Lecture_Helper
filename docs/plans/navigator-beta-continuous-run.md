# Navigator Beta: 전체 과목 연속 실행

## 목표

LNB 첫 과목부터 모든 과목을 순서대로 검사하고, 출석 N·영상 Y인 첫 차시를 사이트 UI로
재생한다. 실제 종료와 새 주차 응답의 출석 Y가 확인되면 같은 과목을 다시 검사하고, 없으면
다음 과목으로 이동한다. 모든 과목에 적격 차시가 없을 때만 종료한다.

## 현재 상태 확인

- POC 3.1은 한 차시의 실제 playing, native ended, 새 응답의 출석 Y를 실측했다.
- POC 3.4는 같은 과목의 다음 차시 actual playing까지 실측했다.
- POC 3.5는 첫 과목부터 6개 과목을 순회해 첫 미수강 차시 actual playing까지 실측했다.
- POC 3.5는 첫 actual playing 직후 의도적으로 종료하므로 연속 실행 상태 전이가 없다.

## 범위와 비목표

- 한 탭에서만 실행하며, 실제 LNB·주차·차시 버튼 클릭과 실제 player 신호만 사용한다.
- 각 차시는 native ended 또는 기존 보조 종료 후보, 유예, fresh AJAX 출석 Y 순서가 모두
  확인된 뒤에만 다음 탐색으로 진행한다.
- 수동 pause는 기존처럼 실제 수동 재생 재개를 기다린다. 자동 `play()`, 시간/진도/출석
  조작, 미확인 RPC 종료 코드 사용은 추가하지 않는다.
- 수동 조작, handoff 불일치·만료, 신호 공백, iframe 교체, 재생/출석 검증 실패는 다른
  차시로 대체하지 않고 중단한다.

## 설계

1. POC 3.5의 과목 handoff를 유지하고, 현재 과목의 `findTarget()`을 매 완료 후 다시 실행한다.
2. 대상 버튼 클릭 뒤 actual playing을 확인하고 기존 관찰 루프로 종료 후보와 출석 Y를 검증한다.
3. 검증 성공 시 완료 기록을 누적하고 대상 player 상태를 초기화한 뒤 같은 과목 재탐색으로
   돌아간다. 대상이 없으면 다음 LNB 과목으로 handoff 이동한다.
4. 완료 리포트에는 과목 순서, 각 완료 대상, 종료 근거, 출석 검증, 마지막 결과를 보존한다.

## 수용 기준

- 첫 과목부터 순서대로 탐색하고 완료 과목은 한 번의 실제 LNB 클릭으로만 넘어간다.
- 매 대상은 actual playing, 실제 종료 근거, fresh attendance Y를 모두 남긴다.
- 출석 Y 확인 전 다음 차시/과목을 클릭하지 않는다.
- 수동 pause·오류·식별 불일치에서는 자동 대체/우회 없이 멈춘다.
- 전 과목 완료일 때만 `PASS_ALL_COURSES_COMPLETED`로 종료한다.

## 검증 계획

1. 두 UserScript 문법 검사, 금지 조작 정적 검사, handoff 및 완료 상태 전이 정적 검사,
   `git diff --check`.
2. 실제 KCU 단일 탭에서 최소 두 차시 연속 완료, 과목 경계 한 번 이동, 수동 pause 대기,
   전체 완료 상태를 별도 리포트로 확인한다.

## 구현 후 검증 기록

- 2026-09-10 Beta 0.4.0 리포트에서 LNB 8개 과목 순회, 세 차시 연속 완료, 세 번의
  native ended 및 첫 fresh AJAX 출석 Y, 최종 `PASS_ALL_COURSES_COMPLETED`를 확인했다.
- 같은 실행에서 수동 pause 및 오류 경로는 발생하지 않았다. 해당 경로는 별도 재현 검증이
  남아 있다.

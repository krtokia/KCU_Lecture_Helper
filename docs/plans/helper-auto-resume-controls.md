# Helper: 비의도적 중지 자동 재개와 제어 설정

## 목표

KCU 플레이어가 실제 재생 직후 약 0.5초에 비의도적으로 pause되는 사례를 Helper가
관찰해 안전하게 재개한다. 자동 재개와 자동 배속을 각각 사용자가 켜고 끌 수 있는
Tampermonkey 영속 설정으로 분리한다.

## 현재 상태 확인

- Navigator POC 3.3의 비영점 재개 실행은 `playing` 뒤 약 0.5초에 trusted media
  `pause`가 발생했고, pause 전 사용자 포인터 입력은 기록되지 않았다.
- 같은 현상은 Helper를 끈 경우에도 발생한다는 사용자 확인이 있다. 따라서 Helper의
  2배속 대입을 단독 원인으로 취급하지 않는다.
- 현재 Helper는 자동 배속을 고정 CONFIG로 적용하고, pause는 알림만 보낸다.

## 범위와 비목표

### 범위

- 실제 재생이 확인된 영상에서, 최근 사용자 입력 흔적이 없는 비의도적 pause를
  자동 재개한다.
- 자동 재개 ON/OFF와 자동 배속 ON/OFF를 독립 GM 저장소 설정 및 메뉴로 제공한다.
- 자동 소리 끄기 ON/OFF를 별도 GM 저장소 설정 및 메뉴로 제공한다.
- ntfy 주소 설정은 유효한 주소를 저장하면 ntfy를 켜고, 빈 값으로 지우면 ntfy를 자동으로
  끈다. 별도의 ntfy ON/OFF 메뉴는 제거한다.
- 재개 시도·성공·실패는 개인정보 없는 콘솔 기록과 기존 알림 흐름으로 구분한다.
- 플레이어 iframe에서 기록한 개인정보 없는 자동 재개 진단을 GM 저장소에 제한된
  개수로 보관하고, 상위 창 Tampermonkey 메뉴에서 복사·파일 저장할 수 있게 한다.

### 비목표

- 사용자의 직접 pause, 탐색, 종료를 무시하고 재생을 강제하는 동작
- Navigator의 차시/과목 선택과 결합
- currentTime·진도·출석 API 조작
- ntfy 주소/배포 URL 변경

## 제약과 설계

- `playing`을 실제 시작 증거로 삼는다. `pause` 후 짧은 지연을 두고 여전히 paused,
  not ended, not seeking일 때만 `video.play()`를 한 번 시도한다.
- 최근 신뢰된 pointer/keyboard 입력 또는 seek이 있으면 사용자의 의도일 수 있으므로
  자동 재개하지 않고 기존 중지 알림만 유지한다.
- 자동 재개 재시도 횟수와 시간 창을 제한해 반복 루프를 막는다.
- `video.play()` Promise가 resolve되어도 재생 증거는 아니므로, 짧은 확인 대기 뒤
  여전히 paused인 경우에만 남은 횟수 안에서 재시도한다. 실제 `playing`이 오면
  타이머를 취소하고 성공으로 기록한다. 이전 재생 요청의 늦은 Promise 완료는 세대
  식별자로 무시해, 새 pause·사용자 조작 뒤의 타이머를 되살리지 않는다.
- 자동 배속 토글은 기존 desired speed 설정만 끄며, 자동 재개와 독립이다.
- 자동 소리 끄기는 기본 꺼짐이고 ON일 때 video 발견 및 실제 재생 시 `muted`만 true로
  적용한다. 볼륨·재생 시간·출석·플레이어 UI 조작은 하지 않는다.
- Tampermonkey 메뉴의 두 토글은 현재 상태를 라벨에 표시하고, 클릭 직후 이전
  명령을 해제·재등록해 라벨도 즉시 다음 상태로 갱신한다.
- cross-origin iframe에서 Helper가 실제 실행되는 기존 구조를 유지한다.

## 수용 기준

- 자동 재개 ON에서 입력 없는 초기 pause는 재생 재개를 한 번 시도한다.
- 사용자 입력 뒤 pause, seeking, ended에는 자동 재개하지 않는다.
- 자동 재개 OFF에서는 기존처럼 pause 알림만 남기고 재생 호출이 없다.
- 자동 배속 OFF에서는 Helper가 playbackRate를 변경하지 않는다.
- 자동 소리 끄기 OFF에서는 Helper가 muted를 변경하지 않고, ON 설정은 새로고침 뒤에도
  유지된다.
- 빈 ntfy 주소 저장 뒤 ntfy는 자동 OFF이며, 유효한 ntfy 주소 저장 뒤에는 자동 ON이다.
- 설정은 새로고침 뒤에도 독립적으로 유지된다.
- Helper 리포트에는 자동 재개 설정, 제한된 이벤트 시각/영상 상태/오류 이름만
  남고 URL·ntfy 주소·키 입력·세션값은 남지 않는다.

## 검증 계획

1. Node 문법 검사와 `video.play()` 호출이 자동 재개 조건 안에만 있는지 정적 검사.
2. 모의 video 이벤트로 입력 없는 pause, 사용자 입력 뒤 pause, seeking/ended pause,
   재생 거부·resolve 뒤 paused 상태·재시도 제한 및 리포트 경계를 검사.
3. 실제 KCU에서 비영점 재개 직후 pause가 발생하면 한 번 재개되는지, 사람의 pause는
   유지되는지 확인한다.

## 구현 기록

- Helper `1.0.7`은 자동 재개 `video.play()` Promise가 resolve된 뒤 1초 안에 실제
  `playing`이 오지 않고 계속 paused인 경우에도 남은 시도 횟수 안에서 재시도한다.
  재생 요청 거부도 같은 제한 아래 재시도하며, 실제 `playing`이 오면 모든 재개 타이머와
  시도 창을 초기화한다. 늦은 Promise 완료가 새 조작 뒤의 재시도를 다시 예약하지 않도록
  요청 세대도 확인한다.
- 상위 창 메뉴에 진단 리포트의 콘솔 출력·복사·파일 저장·초기화를 추가했다. 리포트는
  GM 저장소에 최대 200건의 이벤트 시각, iframe 여부, 숫자형 media 상태, 고정된 원인과
  오류 이름만 보관한다. URL, ntfy 설정, 입력 내용, 세션 데이터는 포함하지 않는다.
- Node 모의 영상에서 (1) resolve 뒤 계속 paused이면 정확히 두 번 시도 후 중단,
  (2) trusted pointer 입력 뒤 pause이면 재생 요청 0회, (3) 재생 성공의 실제 playing이면
  성공 확인 기록을 각각 검증했다. 실제 KCU/Tampermonkey 검증은 아직 필요하다.

## 2026-09-10 설정 간소화 추가 구현

- Helper `1.0.8`은 자동 소리 끄기를 기본 OFF의 독립 GM 설정으로 추가한다. ON이면
  감지·실제 재생 시 `video.muted = true`만 적용한다.
- ntfy 주소 설정/지우기 메뉴는 유효한 HTTPS ntfy.sh 주소 저장 시 ntfy를 자동 ON,
  빈 입력 시 주소 삭제와 ntfy 자동 OFF를 함께 수행한다. ntfy 상태 확인과 독립
  ON/OFF 메뉴를 제거하여 전체 메뉴 수는 9개에서 8개로 줄인다(자동 소리 끄기 1개 추가,
  ntfy 메뉴 2개 제거).
- Node 모의 Tampermonkey 검증에서 자동 음소거 ON의 감지 시 muted 적용, 메뉴 8개,
  빈 주소의 ntfy OFF(기존에 불일치한 ON 값도 정리), 유효한 주소의 ntfy ON을 확인했다.

## 2026-09-10 Helper 1.1.0 안정화 범위

- 자동 재개 진단 이벤트의 수집·저장 코드는 보존하지만, 일상 사용 중 메뉴 과밀을 피하기
  위해 콘솔 출력·복사·파일 저장·초기화 메뉴는 등록하지 않는다.
- ntfy 주소 설정/지우기, 자동 배속, 자동 소리 끄기, 비의도적 중지 자동 재개 메뉴는
  그대로 유지한다.
- 수용 기준은 상위 창 메뉴가 정확히 4개이고 리포트 기능명 메뉴가 노출되지 않으며,
  기존 자동 재개·음소거·ntfy 설정 저장 동작을 바꾸지 않는 것이다.

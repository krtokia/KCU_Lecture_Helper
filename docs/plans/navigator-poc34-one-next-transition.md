# Navigator POC 3.4: 한 차시 완료 뒤 다음 차시 전환

## 목표

현재 과목에서 첫 미수강 영상 차시를 기존의 실제 재생·native 종료·신선한 출석 Y
증거까지 완료한 뒤, 같은 과목 순서에서 다음 미수강 영상 차시를 정확히 하나만
선택하고 실제 `playing`을 확인한다. 두 번째 차시가 재생되면 즉시 POC를 끝낸다.

## 현재 상태 확인

- POC 3.3은 한 차시 범위에서 실제 `playing`, native `ended`, 새 주차 응답의 출석
  Y를 확인해 `PASS_NATIVE_END`를 두 차례 실측했다.
- 2026-09-10의 POC 3.3 무중단 실행은 소비자행동론 2강을 완료했으며, 그 실행에는
  non-end pause가 없었다.
- POC 3.3은 의도적으로 다음 차시를 선택하지 않는다. POC 3.4는 이 경계를 한 번만
  확장한다.

## 범위와 비목표

### 범위

- 현재 과목만 대상으로 한다.
- 첫 대상은 기존의 열린 주차·영상 있음·출석 N 순서 선택 규칙을 사용한다.
- 첫 대상의 출석 Y를 신선한 UI AJAX 응답에서 확인한 뒤에만 다음 대상을 찾는다.
- 같은 주차의 더 큰 차시 번호부터, 그 뒤 열린 주차 순서로 다음 출석 N 영상을
  하나 선택한다.
- 다음 대상의 사이트 버튼 클릭과 해당 iframe의 실제 `playing`을 확인한 즉시 종료한다.

### 비목표

- 다음 대상의 종료·출석 검증 또는 세 번째 차시 선택
- 과목 이동, 출석/시청시간 API 호출, `currentTime`/진도/배속 조작
- 사용자 직접 pause·탐색·과목/주차/차시 조작 무시
- Helper 기능 변경

## 제약과 설계

- 첫 완료 증거는 전환 구조체에 보존한다. 다음 대상 재생을 기다리는 동안 현재
  `state.target`은 다음 대상으로 교체해 iframe identity를 엄격히 검증한다.
- 다음 대상 선택 전 해당 주차를 사이트 UI 클릭으로 다시 불러 서버 응답과 DOM을
  대조한다.
- 첫 대상보다 앞선 같은 주차 차시를 재선택하지 않는다.
- 첫 대상 검증 뒤 다음 적격 차시가 없으면 `PASS_NO_NEXT_ELIGIBLE`로 종료하고,
  재생을 추가로 시도하지 않는다.
- 다음 대상이 실제 재생되지 않으면 `FAILED`이며, 다른 차시로 대체하지 않는다.

## 수용 기준

- 첫 대상의 native ended와 새 출석 Y 확인 전에는 다음 차시 버튼을 클릭하지 않는다.
- 다음 대상은 동일 과목에서 정렬상 첫 대상 다음의 출석 N·영상 Y 차시 하나다.
- `PASS_NEXT_PLAYING`에는 첫 대상·출석 검증·다음 대상·다음 실제 playing 증거가
  모두 남는다.
- 다음 `playing` 확인 뒤에는 어떤 추가 버튼 클릭도 없다.
- 수동 조작, 중단, 타임아웃은 다음 차시 자동 대체나 과목 이동으로 이어지지 않는다.

## 검증 계획

1. Node 문법 검사, diff 검사, Navigator의 `video.play()`/`pause()`/시간·진도 직접
   대입 부재를 정적 확인한다.
2. 순수 선택 보조 함수 모의 입력으로 같은 주차 후속 차시, 다음 주차 차시, 적격
   차시 없음, 앞선 차시 제외를 확인한다.
3. 실제 KCU에서 두 개 이상 미수강 영상이 남은 과목 하나로 실행한다. 첫 차시의
   출석 Y와 다음 차시의 실제 `playing`만 확인된 `PASS_NEXT_PLAYING` 리포트를
   저장한다.
